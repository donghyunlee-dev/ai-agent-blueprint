# 개발 단위 작업 설계

## 목적

이 디렉터리는 PRD를 실제 개발 작업으로 전환하는 작업 설계와 참고 기준을 담는다. 작업 문서에서 기능 범위와 수용 기준을 확인하고, 변경 범위에 맞는 검증을 실행한다.

[개발 PR·리뷰·QA 워크플로](development-pr-review-qa-workflow.md)는 참고 자료다. 별도 planner, reviewer, QA agent나 전체 PR 절차를 자동으로 요구하지 않는다.

## 작업 단위 기준

하나의 작업 단위는 다음 조건을 모두 만족해야 한다.

- 하나의 사용자 결과 또는 하나의 기술 계약을 완성한다.
- 독립적으로 검증할 수 있는 정상 결과와 실패 결과가 있다.
- 변경할 도메인, API, 화면과 저장 범위를 식별할 수 있다.
- 완료 여부를 관찰 가능한 문장으로 판정할 수 있다.
- 다음 작업이 의존할 산출물을 명시한다.

파일 수나 코드 줄 수는 작업 단위 기준으로 사용하지 않는다. UI와 저장·API가 함께 바뀌더라도 하나의 사용자 결과를 완성한다면 같은 작업 단위로 관리한다.

## 작업 상태

| 상태 | 의미 | 다음 상태 조건 |
| --- | --- | --- |
| `blocked` | 필수 결정이나 선행 계약이 없음 | 결정 기록 또는 선행 산출물 확정 |
| `ready` | 입력과 완료 기준이 확정됨 | 선행 PR 머지 후 구현 시작 |
| `in_progress` | 구현 또는 자체 테스트 진행 중 | PR과 필수 증거 준비 |
| `code_review` | 필요 시 코드 리뷰 중 | 적용할 finding을 처리 |
| `qa` | 필요 시 동작·프로세스 QA 중 | 적용할 finding을 처리 |
| `fix_required` | 수정 필요 | 수정 후 관련 검증 재실행 |
| `ready_to_merge` | 변경에 맞는 검증을 마친 병합 대기 상태 | 사용자가 병합 여부를 결정 |
| `done` | 기본 브랜치 병합 확인 완료 | 후속 작업 시작 가능 |

## 공통 작업 문서 구조

모든 단계 문서는 다음 항목을 포함한다.

1. 목표와 사용자 결과
2. 포함 범위와 제외 범위
3. 연결된 요구사항과 결정
4. 선행 조건
5. 작업 단위별 입력·구현·출력·수용 기준
6. 화면과 상태 표현
7. 데이터와 API 영향
8. 실패·빈 상태·접근성
9. 테스트 시나리오
10. 완료 정의와 제출 증거

## 공통 완료 정의

작업은 코드가 작성됐다는 이유만으로 완료되지 않는다. 다음 항목을 모두 충족해야 `done`이다.

- 변경에 직접 적용되는 수용 기준을 관련 자동 테스트 또는 수동 확인으로 검증했다.
- 오류·빈 상태·재시도 등 변경에 영향받는 경로를 확인했다.
- UI 변경이면 `docs/blueprint-design/README.md`의 관련 주 시안과 필요한 `docs/template/README.md` 상태 캡처를 확인하고 구현 근거를 작업 기록에 남겼다.
- [상세 화면 설계](../ui/README.md)의 해당 `UI-*` 식별자와 필수 viewport·상태 증거를 충족했다.
- semantic HTML/CSS와 기존 React 구조를 사용했고 새 UI design system dependency를 추가하지 않았다.
- 키보드, 포커스, 이름·설명·오류 연결을 확인했다.
- 데스크톱과 해당 단계에서 요구하는 모바일 상태를 확인했다.
- production code/build 설정 변경이면 관련 build를 확인한다.
- API 키, Google OAuth secret, 로그인 token, 사용자 원문과 파일 내용이 로그·번들·스크린샷에 노출되지 않는다.
- 변경 파일, 테스트 결과, 알려진 제한과 후속 작업을 인계 기록에 남겼다.
- 리뷰·QA가 요청되었거나 변경 위험상 필요한 경우 그 결과와 조치를 기록한다.
- 병합은 사용자가 명시적으로 승인한 경우에만 진행한다.

## 권장 검증 기록

| 변경 종류 | 증거 |
| --- | --- |
| 도메인 규칙 | 단위 테스트 이름과 통과 결과 |
| API 계약 | 정상·오류 fixture와 계약 테스트 결과 |
| 저장 | 새로고침·마이그레이션·실패 복구 결과 |
| UI | 최종 HEAD의 데스크톱·모바일 캡처를 PR에서 직접 볼 수 있는 링크, Playwright Chromium·키보드 검증 결과; Agent Browser를 사용할 수 있으면 같은 흐름의 추가 검증 결과 |
| Agent 동작 | 요청/응답 스키마 fixture, 잘못된 응답 거절 결과 |
| 다운로드 | 생성 파일명과 Markdown 내용 검증 결과 |

증거 파일은 PR 또는 작업 기록에 첨부하고 저장소 루트에 임시 이미지나 로그로 남기지 않는다. UI 캡처 attachment 업로드가 불가능할 때만 최종 최적화 이미지를 `docs/delivery/evidence/<pr-unit>/`에 보관한다.

## 미결정 차단 규칙

미결정 항목이 작업 결과를 바꾸면 구현자가 임의로 선택하지 않는다. 해당 작업을 `blocked`로 두고 [결정 기록](../product/10-decision-log.md)에 결정이 추가된 뒤 문서를 갱신한다.

현재 차단 후보:

- 브라우저 지원과 프로젝트 백업: 관련 단계 시작 전 필요
