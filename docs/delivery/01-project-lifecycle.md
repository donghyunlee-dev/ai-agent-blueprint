# 1단계 — 프로젝트와 저장

## 목표와 사용자 결과

사용자가 홈에서 새 Blueprint를 만들고, 새로고침하거나 브라우저를 닫았다가 다시 열어도 마지막 작업을 이어간다. 최근 프로젝트가 20개를 초과하면 데이터가 조용히 삭제되지 않고 사용자가 삭제 대상을 확인한다.

이 단계는 `AUTH-001`~`AUTH-006`이 완료되어 현재 인증 사용자의 owner namespace가 제공되는 것을 선행 조건으로 한다.

## 연결 기준

- 화면 설계: [홈·프로젝트·파일](../ui/05-home-projects-and-files.md), [작업 공간 셸](../ui/01-workspace-shell.md), [홈 화면 청사진](../ui/screens/01-home-and-start.md)

- 요구사항: `PJT-001`~`PJT-005`, `NFR-002`, `NFR-004`
- 결정: `DEC-001`, `DEC-003`, `DEC-011`, `DEC-014`, `DEC-017`, `DEC-018`, `DEC-020`
- 선행 조건: FND-001~005 완료

## 사용자 흐름

```text
홈
→ 아이디어 입력 또는 파일 선택
→ 프로젝트 생성
→ /blueprints/:projectId
→ 자동 저장
→ 새로고침/재방문
→ 마지막 프로젝트·탭·스크롤 복구
```

20개 초과 흐름:

```text
21번째 생성 요청
→ 가장 오래된 프로젝트와 삭제 범위 표시
→ 취소: 기존 목록 유지, 생성 중단
→ 삭제 확인: 대상 영구 삭제, 새 프로젝트 생성
```

## 작업 단위

### PRJ-101 라우팅과 404

구현:

- `/`, `/blueprints/new`, `/blueprints/:projectId`, `/blueprints/:projectId/:documentType`을 구성한다.
- `/survey`, `/prd`와 알 수 없는 경로는 공통 404로 보낸다.
- 존재하지 않는 project ID는 일반 404와 구분해 프로젝트 없음 안내를 보여준다.

화면:

- 일반 404: `홈으로`, `새 Blueprint 시작`
- 프로젝트 없음: `최근 프로젝트`, `새 Blueprint 시작`
- 자동 리다이렉트는 하지 않는다.

성공 조건:

- 브라우저 뒤로가기와 직접 URL 접근이 일관되게 동작한다.
- 이전 URL에서 이전 화면이 렌더링되지 않는다.

### PRJ-102 홈과 새 프로젝트 생성

입력:

- 선택적 제목
- 필수 첫 설명
- 선택적 참고 파일

구현:

- 제목이 없으면 첫 설명을 100자 이내 안전한 임시 제목으로 변환한다.
- UUID, 생성 시간, 단일 thread와 초기 readiness를 만든다.
- 첫 설명을 사용자 메시지로 한 번만 기록한다.

화면 상태:

- 초기: 3~5줄 입력, 파일 첨부, 예시 2~3개
- 검증 오류: 해당 입력과 연결된 한글 오류
- 생성 중: 중복 제출 차단
- 성공: 새 작업 공간으로 이동

성공 조건:

- 공백 입력으로 프로젝트가 생성되지 않는다.
- 빠른 연속 클릭에도 프로젝트와 첫 메시지가 하나만 생성된다.

### PRJ-103 IndexedDB 저장소

구현:

- 새 namespace와 `schemaVersion`을 가진 IndexedDB repository를 구현한다.
- 프로젝트 aggregate와 activity를 하나의 트랜잭션으로 저장한다.
- 변경 후 500ms 이내 debounce 저장을 예약한다.
- 마지막 프로젝트 ID, 활성 탭과 UI 환경설정만 localStorage에 둔다.

성공 조건:

- 새로고침 후 마지막 완료 저장본을 복구한다.
- 저장 중 추가 편집이 유실되지 않는다.
- quota 또는 transaction 실패 시 메모리의 작업 복사본을 유지한다.
- 이전 앱 저장 key를 읽거나 변환하지 않는다.

### PRJ-104 최근 프로젝트와 20개 제한

구현:

- 최근 프로젝트를 `lastOpenedAt` 내림차순으로 표시한다.
- 21번째 생성 전에 현재 프로젝트를 제외한 최오래 프로젝트를 계산한다.
- 삭제 확인 modal에 제목, 최종 수정 시각, 문서·첨부 포함 삭제와 복구 불가를 표시한다.

화면 행동:

- `취소`: modal 닫기, 생성하지 않음
- `삭제하고 새로 만들기`: 영구 삭제 후 생성
- 삭제 처리 중 modal을 닫거나 중복 실행할 수 없음

성공 조건:

- 확인 없이 데이터가 삭제되지 않는다.
- 삭제 실패 시 새 프로젝트를 만들지 않고 기존 데이터를 유지한다.
- 목록에는 최대 20개만 남는다.

### PRJ-105 작업 공간 셸과 복구

구현:

- 상단에 프로젝트명, 설계·요구사항명세서·PRD 탭, 저장 상태와 내보내기 진입점을 둔다.
- 대화, 중앙 작업 영역과 상세 영역의 빈 상태를 구성한다.
- 마지막 문서 탭과 대화 위치를 복구한다.

저장 상태 문구:

- `저장 중`
- `저장됨 · HH:mm`
- `저장 실패 · 다시 시도`

성공 조건:

- 저장 상태를 색상만으로 표현하지 않는다.
- 모바일에서는 대화·설계/문서·검토 탭으로 전환한다.
- 빈 영역마다 무엇이 표시될지와 다음 행동 하나를 안내한다.

## 필수 테스트

1. 제목 있음/없음 프로젝트 생성
2. 중복 클릭과 동일 UUID 충돌 방지
3. 자동 저장 후 새로고침 복구
4. 저장 중 새 입력과 저장 실패 재시도
5. 20개 이하 생성 시 삭제 확인 없음
6. 21번째 생성 취소와 삭제 확인 각각 검증
7. 이전 저장 key 미사용
8. `/survey`, `/prd`, 임의 URL과 없는 프로젝트 URL
9. 데스크톱·모바일 셸과 키보드 탐색

## 완료 증거

- IndexedDB repository 단위/통합 테스트
- 20개 경계값 E2E
- 저장 실패 fixture 결과
- 홈, 삭제 확인, 작업 공간, 404의 데스크톱·모바일 캡처
- 키보드 포커스 순서 기록

## 단계 종료 조건

서버와 AI 없이도 프로젝트 생성, 자동 저장, 재개, 20개 제한 처리와 404가 동작해야 한다. 다음 단계는 이 저장소와 셸을 교체하지 않고 사용해야 한다.
