# 2단계 — 대화와 선택 폼

## 목표와 사용자 결과

사용자가 아이디어를 설명하면 Agent가 설계 후보를 찾고, 현재 공백에 맞는 한 가지 질문을 선택형 또는 직접 입력형 폼으로 이어간다. 오류가 발생해도 입력을 잃지 않으며 가짜 결과를 표시하지 않는다.

## 연결 기준

- 화면 설계: [대화와 선택 폼](../ui/02-conversation-and-forms.md), [첫 분석과 연속 질문 청사진](../ui/screens/02-intake-and-discovery.md)

- 요구사항: `CONV-001`~`CONV-005`, `FORM-001`~`FORM-004`, `NFR-004`, `NFR-006`
- 결정: `DEC-006`, `DEC-007`, `DEC-009`, `DEC-010`, `DEC-014`, `DEC-020`
- 선행 조건: 1단계 repository와 단일 conversation thread 완료
- AI 실행 계약: [AI 모델·프롬프트·평가 작업 설계](ai-model-prompt-and-evaluation.md) `AI-001`~`AI-005`, `AI-008`~`AI-010`

## 화면 구조

- 패널 상단: 현재 설계 영역, 질문 제목과 질문 이유
- 질문 카드: 설명, 필수 여부, 선택 폼, 불확실성 행동, 제출
- 대화 이력: 사용자 원문, Agent 설명, 질문 요약, 오류
- 하단 입력: 자유 입력, 전송, 파일 첨부 진입
- 작업 상태: 현재 단계 이름과 취소

Agent 이름이나 모델명보다 현재 수행 중인 작업과 사용자에게 필요한 행동을 먼저 보여준다.

## 작업 단위

### CON-201 프로젝트별 AI 데이터 안내

구현:

- 프로젝트의 첫 AI 전송 직전에 데이터 처리 안내를 표시한다.
- 전달 범위, 외부 AI 처리, 민감정보 제거와 취소 결과를 설명한다.
- 확인 시 프로젝트에 동의 시각과 안내 버전을 저장한다.

성공 조건:

- 프로젝트마다 최초 한 번만 표시된다.
- 취소하면 입력을 유지하고 네트워크 요청을 보내지 않는다.
- 안내 버전이 바뀌면 재확인할 수 있는 데이터 구조를 가진다.

### CON-202 turn API와 요청 수명주기

구현:

- `POST /api/blueprint/turn` 요청과 strict response 검증을 구현한다.
- 자유 답변은 `TURN_ANALYZE` DEFAULT, 질문은 catalog 기본 문구와 필요한 경우의 `QUESTION_COMPOSE` LIGHT로 분리한다.
- 응답은 허용된 DisplayBlock과 복수 atomic proposal을 함께 반환한다.
- 사용자 의도마다 `logicalRequestId`, 실행 시도마다 `attemptId`를 발급하고 실행 중 중복 전송과 중복 반영을 차단한다.
- 성공 전에는 프로젝트의 확정 설계를 변경하지 않는다.
- 취소는 네트워크 요청과 generation job을 `cancelled`로 종료한다.

상태:

```text
idle → queued → running → succeeded
                     ├→ failed
                     └→ cancelled
```

성공 조건:

- 같은 request를 재시도해도 Assistant 메시지와 제안이 중복되지 않는다.
- schema 오류는 `AI_INVALID_OUTPUT`으로 변환되고 payload가 저장되지 않는다.
- API 키와 공급자 오류 원문이 클라이언트에 노출되지 않는다.

### CON-203 질문 카탈로그와 선택 엔진

구현:

- 12개 설계 영역별 질문 후보, 선행 조건, 필수성, 허용 폼과 대상 item type을 정의한다.
- 필수성, 후속 영향, 위험, 불확실성, 직전 맥락과 피로도로 정렬한다.
- 동점이면 문제·사용자·목표를 기능·기술보다 먼저 선택한다.

성공 조건:

- 이미 확정된 의미를 다시 묻지 않는다.
- 로그인 불필요 시 로그인 방식 질문이 나타나지 않는다.
- 데이터 불필요 시 DB 종류 질문이 나타나지 않는다.
- 한 화면에는 주요 질문 하나만 나타난다.

### CON-204 동적 선택 폼

| answer mode | 화면 | 검증 결과 |
| --- | --- | --- |
| `single` | 5개 이하 Radio 카드, 초과 시 목록 | 하나의 안정된 value |
| `multiple` | Checkbox 또는 MultiSelect | value 배열, 최대 수 검증 |
| `text` | Textarea | 공백 제거 후 원문 유지 |
| `number` | NumberInput | min/max와 단위 검증 |
| `range` | 시작·끝 입력 | 역전 범위 거절 |
| `rank` | 선택 후 순서 지정 | 중복 없는 순위 배열 |
| `confirm` | 발견 항목 목록과 확인 | 항목별 확인 결과 |

공통 행동:

- `직접 입력`은 표준 선택과 함께 제출할 수 있다.
- `잘 모르겠어요`는 설명을 요청한다.
- `추천해 주세요`는 제안을 만들지만 자동 선택하지 않는다.
- `나중에 결정`은 `deferred` 항목을 만든다.
- 선택적 질문만 `건너뛰기`를 제공한다.
- 표준 선택·skip·defer는 별도 분석 모델을 호출하지 않는다.

성공 조건:

- 지원하지 않는 answer mode는 안전한 text 폼으로 대체한다.
- 모든 폼이 label, description, error와 연결된다.
- 선택 즉시 제출하지 않고 사용자가 제출 행동을 수행한다.
- 키보드만으로 입력, 순위 변경과 제출이 가능하다.

### CON-205 메시지와 진행 상태

구현:

- 사용자 메시지, Agent 메시지, 질문, 작업 상태와 오류를 의미별로 렌더링한다.
- 오래된 대화는 구조화 요약으로 대체하되 원문과 출처를 구분한다.
- 알 수 없는 진행률에 백분율을 표시하지 않는다.

표시 예:

```text
답변 분석 중
✓ 관련 사용자 후보 확인
• 기능 후보 정리 중
• 다음 질문 준비 중
```

성공 조건:

- 새 작업 상태와 오류는 live region으로 전달된다.
- 긴 메시지는 접을 수 있지만 주요 결론과 행동은 접히지 않는다.
- 새로고침 후 현재 질문과 미전송 입력을 복구한다.

### CON-206 오류와 재시도

오류별 화면:

| 오류 | 유지할 것 | 제공할 행동 |
| --- | --- | --- |
| 네트워크 실패 | 작성 입력, 질문, 확정 설계 | 다시 시도, 입력 수정 |
| rate limit | 동일 | 대기 안내, 다시 시도 |
| schema 실패 | 원래 입력, 기존 상태 | 다시 시도 |
| 취소 | 원래 입력, 마지막 저장본 | 다시 시작 |

성공 조건:

- fallback 제안이나 문서를 만들지 않는다.
- 오류 재시도 후 같은 request 결과가 한 번만 반영된다.
- 오류 메시지는 원인 범주와 다음 행동을 한국어로 설명한다.

## 필수 테스트

1. 첫 AI 요청 안내 확인/취소/재진입
2. 각 answer mode 정상·경계·오류 입력
3. 조건부 질문 활성·비활성
4. 동일 의미 반복 질문 방지
5. 추천 요청이 자동 확정되지 않음
6. 미정과 건너뛰기의 다른 저장 결과
7. schema 오류, 네트워크 오류, 취소와 재시도
8. 중복 request 반영 방지
9. 키보드와 screen reader 이름·오류 연결
10. 모바일 입력창과 가상 키보드 상태

## 완료 증거

- 질문 카탈로그 목록과 조건표
- 모든 폼의 컴포넌트 테스트
- 정상·오류 API fixture
- 질문 선택 규칙 단위 테스트
- 대화 정상·오류·모바일 화면 캡처

## 단계 종료 조건

첫 설명부터 조건부 연속 질문까지 진행할 수 있고, 모든 허용 폼과 오류 재시도가 저장·복구되어야 한다. 확정 설계 반영은 3단계 제안 승인 규칙을 통과해야 한다.
