# 작업 공간 셸

## UI-SHELL-001 사용자 목표

사용자가 대화, 제안 검토, 설계, Requirements, PRD 사이를 이동해도 프로젝트 제목, 저장 상태, 이전 결정과 현재 작업을 잃지 않는다. 시각 기준은 [대화 시안과 화면별 매핑](../blueprint-design/README.md)이다.

## 공통 프레임

```text
지원 목적지 탐색 │ 프로젝트 제목 · 저장 상태 │ 사용자 행동
대화 → 제안 검토 → 설계 → Requirements → PRD
현재 단계의 주 작업 영역 │ 해당 단계의 보조 영역
```

- 홈으로 이동, 현재 프로젝트, 저장 중/저장됨/실패, 로그인 사용자와 로그아웃을 실제 상태로 표시한다.
- 전역 탐색은 현재 구현된 목적지만 노출한다. Templates, Knowledge Library, Settings, 알림과 새 프로젝트 대시보드의 빈 메뉴를 두지 않는다.
- 단계 표시는 실제 URL 또는 프로젝트 내부 mode와 동기화한다. `설계`, `Requirements`, `PRD`의 기존 문서 경로를 유지하고 `대화`, `제안 검토`는 구현된 프로젝트 내 상태로 이동한다.
- Requirements는 기존 준비도, PRD는 ready Requirements의 gate와 이유를 보여준다. 잠긴 단계도 설명과 돌아갈 행동을 제공한다.
- setup guide는 PRD 뒤의 기존 산출물로 접근시키며 단계 표시의 여섯 번째 항목으로 만들지 않는다. 자료, 정합성 검토와 내보내기도 현재 흐름에서 계속 찾을 수 있다.

## 단계별 주·보조 영역

| 단계 | 주 작업 영역 | 보조 영역 |
| --- | --- | --- |
| 대화 | 메시지, 현재 질문, composer, Agent 상태 | 확정·미결정 요약과 참고 자료 |
| 제안 검토 | 미처리 제안, 근거, 개별·일괄 처리 | 확정 내용, 남은 수와 영향 |
| 설계 | 5개 준비 요약과 10개 원본 영역·항목 | 선택 항목의 근거·상세·blocker |
| Requirements | 목차, 섹션 요약·본문·편집 | review/stale/conflict 문제와 문서 행동 |
| PRD | 목차, 섹션 요약·본문·편집 | 요구사항 연결·문서 상태와 행동 |

요약·상세는 선택한 단계에 종속된다. 데스크톱에서도 상시 3패널을 강제하지 않으며, 오버레이가 필요할 때만 해당 작업에 열고 닫는다.

## 스크롤과 저장

- 프레임과 단계 탐색은 읽기 중 현재 위치를 알 수 있게 유지한다. 긴 주 영역과 보조 영역은 필요한 곳에서만 독립 스크롤한다.
- 대화 composer는 대화 단계에서 접근 가능하며 긴 대화 읽기와 입력을 동시에 방해하지 않는다. 과거 메시지를 보는 중에는 자동으로 하단으로 이동시키지 않는다.
- 저장 실패는 프레임의 저장 상태와 영향을 받은 편집 영역에서 알린다. 미저장 입력, 현재 단계, 선택 항목을 유지하고 다시 시도할 수 있다.
- 기존 대화 폭 preference가 적용되는 레이아웃에서는 값을 유지한다. 다른 단계에 동일 폭의 빈 열을 남기지 않는다.

## 반응형·접근성

- 1440×900·1280×800: 현재 단계의 주 작업을 중심으로 배치하고 해당 보조 영역을 함께 읽는다.
- 1024×768·768×1024: 좁아진 폭에 맞춰 보조 영역을 아래로 보내거나 명시적 제어로 연다. 문서 본문과 제안 행동의 읽기 폭을 우선한다.
- 390×844: 한 열로 현재 단계의 콘텐츠를 읽는다. 단계와 보조 영역은 접근 가능한 탐색·버튼으로 연다. 숨긴 영역은 Tab 순서와 접근성 트리에서 제외한다.
- URL 이동은 링크, 같은 URL 안의 mode 전환은 버튼 또는 실제 tab semantics를 쓴다. 선택·닫기 후 포커스는 단계 제목 또는 원래 trigger로 돌아간다.
- 200% 확대, 긴 프로젝트명, 긴 제안, 키보드 열린 상태와 OS safe area에서도 행동이 가려지지 않는다.

## 완료 판정

- 다섯 단계의 위치와 gate가 실제 route·데이터에 맞는다.
- 저장·인증·지원 행동이 각 단계에서 계속 접근 가능하다.
- 긴 콘텐츠, overlay, 저장 실패, 5개 뷰포트에서 주·보조 콘텐츠와 포커스 순서가 유지된다.
