# 시각 기반과 CSS 기준

## 화면 논지

- 현재 프로젝트와 `대화 → 제안 검토 → 설계 → 요구사항 명세 → PRD` 단계를 먼저 이해할 수 있다.
- 선택한 단계의 작업이 가장 넓고 먼저 읽히며, 요약·근거·목차·상세는 단계에 필요한 보조 영역으로 배치한다.
- AI 결과는 제안과 승인을 거쳐 반영한다. 상태를 색상 또는 임의 수치만으로 설명하지 않는다.
- 주 시안은 [Blueprint 디자인 매핑](../blueprint-design/README.md)이다. 로그인과 시안에 없는 상태는 [template 목록](../template/README.md)을 사용한다.

## 기준 뷰포트

| 이름 | viewport | 검수 목적 |
| --- | --- | --- |
| Desktop wide | 1440 × 900 | 공통 프레임과 단계별 주·보조 영역 |
| Desktop minimum | 1280 × 800 | 긴 제목·제안·문서의 가용 폭 |
| Compact | 1024 × 768 | 보조 영역 재배치와 오버레이 |
| Tablet portrait | 768 × 1024 | 단계 이동과 콘텐츠 순서 |
| Mobile | 390 × 844 | 한 열, composer/footer와 safe area |

200% 확대에서 주요 콘텐츠와 행동이 사라지지 않아야 한다. 브레이크포인트는 고정 패널 수가 아니라 콘텐츠가 읽히는 폭을 기준으로 구현 PR에서 결정한다.

## 앱 범위 CSS 변수

반복되는 배경·표면·본문·보조 글자·구분선·파란색 강조·상태색, 간격·반경·그림자는 앱 범위 custom properties로 묶는다. 화면별 레이아웃 값은 해당 화면 CSS에 두고 반복될 때만 공통 변수로 승격한다. 이 문서는 새로운 UI package나 별도 디자인 시스템을 요구하지 않는다.

| 역할 | 시각 계약 |
| --- | --- |
| 앱 배경과 표면 | 밝은 중립 캔버스, 흰색 주 표면, 절제된 경계 |
| 제목과 본문 | 짙은 본문색과 읽기 쉬운 긴 문서 줄 높이 |
| 선택·진행·주요 행동 | 시안의 파란색 계열을 일관되게 사용하고 텍스트·아이콘 상태를 함께 표시 |
| 확정·검토·경고·오류 | 의미가 구분되는 텍스트와 보조 색·아이콘 |
| 카드와 오버레이 | 필요한 정보 그룹에만 카드; Drawer/Modal은 위계와 포커스 계약을 보존 |

홈의 시작 입력과 최근 프로젝트, 대화의 현재 질문, 제안의 항목별 행동, 설계의 준비 카드, 문서의 목차·섹션이 화면별 주요 위계다. 로고·프로필·사무실 사진은 시안의 예시 이미지이며 신규 자산으로 만들지 않는다.

## 간격·타이포그래피·모션

- 같은 관계의 요소는 같은 간격을 쓴다. 아이콘·라벨, 폼 필드, 카드 내부, 섹션 사이 간격을 각 화면에서 일관되게 유지한다.
- 화면 제목, 섹션 제목, 본문, 메타데이터의 네 단계 위계를 구분한다. 메타데이터 크기의 글씨로 본문을 대체하지 않는다.
- 문서 본문은 읽기 폭을 제한하고 긴 한국어 문장, 긴 파일명, 확대 상태에서 줄바꿈을 허용한다.
- `prefers-reduced-motion`에서는 위치 이동 애니메이션을 제거한다. 실제 처리 단계가 없는 작업에 가짜 진행률·퍼센트를 만들지 않는다.

## 완료 기준

- 다섯 기준 뷰포트와 200% 확대에서 수평 잘림, 가려진 행동, 숨은 포커스가 없다.
- 색상·상태·본문 위계가 주 시안과 제품 상태 계약에 맞는다.
- 실제 구현 화면의 1440×900과 390×844 최종 HEAD 캡처가 행동 검증과 일치한다.
