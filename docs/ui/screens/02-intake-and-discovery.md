| ID | 의미 | 판정 |

| D02 | Agent 맥락 | Card 없이 body 흐름 |
| D03 | 완료 답변 | 질문과 확정값 한 줄, 수정 가능 |
| D04 | 영역/필수 | Badge, 질문 제목보다 약함 |

## 제안 gate 변형

답변 분석 후 D04 위치는 다음 요약으로 바뀐다.

```text
검토할 제안 3개
답변에서 사용자 1개와 기능 2개를 찾았습니다.
[제안 검토]
다음 질문은 제안을 모두 처리한 뒤 표시됩니다.
```

자유 composer는 유지된다. `다음 질문` disabled button을 별도로 크게 노출하지 않고 설명과 제안 검토 행동을 우선한다.

## 도움·추천 block 변형

`잘 모르겠어요`를 선택하면 D04 위에 explanation block을 표시한다.

```text
선택 기준을 간단히 설명할게요.
• 옵션 A — 적합한 상황과 주의점
• 옵션 B — 적합한 상황과 주의점
[질문으로 돌아가기]
```

Question ID와 입력 상태는 유지한다.

`추천해 주세요`를 선택하면 recommendation block을 표시한다.

```text
추천 · 옵션 A
현재 확정된 목표와 사용자 규모에 가장 잘 맞습니다.
고려할 점: 운영 비용, 권한 설정
[추천 제안 검토]
```

추천 option은 checked가 아니며 proposal 승인 전 설계에 반영되지 않는다.

## Mobile

- 이 Frame에서는 `대화` 모드만 보이고 AppBar 아래 모드 탭에 `설계`, `검토 3`이 유지된다.
- QuestionCard가 viewport 전체 높이를 강제로 차지하지 않는다.
- D09는 카드 footer이며 화면 하단 고정이 아니다. D10 composer만 safe-area 위에 고정한다.
- 키보드가 열리면 현재 FormField 또는 composer 중 사용 중인 입력이 보이도록 scroll한다.

## 수용 기준

- 첫 분석 중 중앙과 상세의 빈 상태가 오류처럼 보이지 않는다.
- 현재 질문, 이유, 선택지, 미정 행동, 제출 순서가 DOM과 시각에서 같다.
- 추천 option이 기본 선택되지 않는다.
- 제안 gate에서도 D10 자유 입력과 과거 답변 수정 진입이 가능하다.
- 실패 후 동일 Frame에서 사용자 원문과 선택 상태가 유지된다.
- 설명, 추천과 복수 제안 요약이 서로 다른 시각 구조와 행동으로 구분된다.
