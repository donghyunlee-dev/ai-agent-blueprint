## 요소 계약

| ID | 컴포넌트 | 위치·규격 | 상태/행동 |
| --- | --- | --- | --- |
| H01 | `Typography h4` + home link | AppBar 왼쪽 `--page-padding` | 현재 페이지, 별도 Card 없음 |
| H02 | `Button ghost sm` | AppBar 오른쪽 | 제품 사용 흐름 섹션으로 이동 |
| H03 | `Typography h1` | hero 중앙, 최대 문서 폭 | 두 줄 이내 |
| H04 | `Typography body` | H03 아래 `--spacing-md` | 한 문장 |
| H05 | `FormField` + `Textarea` | composer 본문, 최소 4행 | 값 trim, 글자 오류 inline |
| H06 | `Button ghost` + `FileUpload` trigger | composer footer 왼쪽 | 파일 선택, 자동 생성 안 함 |
| H07 | `Button primary lg` | footer 오른쪽 | 유효 입력 또는 사용 가능 파일 필요 |
| H08 | `ChipGroup` 또는 ghost buttons | composer 아래 | Textarea 채움, 제출 안 함 |
| H09 | semantic figure | hero 다음 | 장식 통계 없이 한 장면 |
| H10 | `Typography h3` | 다음 섹션 시작 | recent count 없음 |
| H11 | `EmptyState` | 목록 영역 | 행동은 H05 포커스 이동 |

주 시안은 [홈 디자인](../../blueprint-design/README.md)이다. H01·H02는 실제 홈/사용 방법 목적지만 보여준다. H09는 현재 구현된 작업 흐름 안내이며 사진·샘플 프로젝트·템플릿·지식 라이브러리 카드를 새로 만들지 않는다.

## Mobile

- H01/H02는 동일한 한 줄 AppBar다.
- H03는 3줄을 넘지 않고 좌우 `--spacing-md`를 유지한다.
- composer footer는 H06과 H07을 세로로 쌓지 않는다. H06은 icon+짧은 label, H07이 남은 폭을 가진다.
- H09 작업 흐름 안내는 좁은 폭에서 순서대로 읽힌다.
- viewport 첫 화면에서 H03, H04, H05 상단과 H07이 모두 인지 가능해야 한다.

## F-HOME-RECENT

H11 대신 프로젝트 Card가 최근 순으로 표시된다.

```text
[프로젝트명]                       [작업 가능]
마지막 수정 2026.09.15 · 요구사항 명세 작성 중
                                           [계속하기]
```

실제 최근 프로젝트 데이터만 표시한다. 데스크톱의 여러 열은 가용 폭에 따라 줄이고 모바일에서는 한 열로 읽는다. Card hover만으로 행동을 숨기지 않는다. 별도 `전체 보기` route는 추가하지 않는다.

## F-PROJECT-LIMIT

Modal 기본 copy:

- 제목: `오래된 프로젝트를 삭제하고 새로 만들까요?`
- 설명: `브라우저에는 최대 20개를 보관할 수 있습니다.`
- 대상: `{프로젝트명} · 마지막 수정 {날짜}`
- 경고: `대화, 설계, 문서와 첨부 자료가 영구 삭제되며 복구할 수 없습니다.`
- 행동: `취소`, `삭제하고 만들기`

## 수용 기준

- H03와 H07이 시각적 1·2순위이며 H09가 경쟁하지 않는다.
- 빈 홈에서 사용자가 5초 안에 시작 입력 위치를 찾는다.
- 최근 프로젝트가 6개여도 새 프로젝트 composer가 첫 viewport에서 사라지지 않는다.
- 제한 Modal 취소 후 H05 입력과 파일 선택이 유지된다.
