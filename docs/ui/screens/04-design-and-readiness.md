## 상태 위계

- S02는 전체 상태 하나와 원인 요약이며 dashboard 지표 Card로 만들지 않는다.
- S03은 누락/review_required 항목 filter를 적용한다.
- S04~S06은 section heading + count + 구분선 item rows다.
- 상태 count의 분모는 해당 영역의 현재 필수 항목 수이며 전체 설문 문항 수가 아니다.
- S07은 중앙 본문 마지막의 생성 gate다. sticky CTA로 문서 읽기를 계속 방해하지 않는다.

## 설계 영역 순서

1. 제품 정의
2. 문제와 목표
3. 사용자와 역할
4. 시나리오
5. 핵심 기능과 수용 기준
6. 범위와 제외 범위
7. 데이터와 외부 연동
8. 인증과 권한
9. 운영·배포·보안 제약
10. 성공 기준과 위험

확정 항목이 없는 섹션도 삭제하지 않는다. 제목, 상태, 빈 이유와 `대화에서 결정` 행동을 보여준다.

## Requirements 생성 gate

| 준비 상태 | S07 문구 | S08 |
| --- | --- | --- |
| insufficient | `필수 항목 {N}개를 결정해야 합니다.` | disabled + 부족 항목 보기 |
| workable | `명시적으로 미룬 항목은 오픈 이슈로 포함됩니다.` | enabled |
| ready | `핵심 설계와 수용 기준이 준비되었습니다.` | enabled primary |
| conflict | `충돌 {N}개를 먼저 해결해야 합니다.` | disabled + 충돌 검토 |

사용자에게 readiness 숫자 점수는 표시하지 않는다.

## Inspector 편집

`편집`은 현재 항목을 제안 상태로 수정한다. 확정값을 직접 덮어쓰지 않는다.

1. 현재값을 field에 표시
2. 수정 이유 선택 또는 입력
3. 영향 예상 표시
4. `변경안 만들기`
5. proposal review로 이동

문서 직접 편집만 영향 미리보기 후 공통 설계에 자동 반영한다는 별도 규칙과 혼동하지 않는다.

## Mobile

- `설계` 모드에 S01~S08만 표시한다.
- S04~S06 section은 첫 방문에는 펼침, 사용자가 접은 상태를 UI preference로 유지한다.
- item 선택 시 Inspector Drawer를 열고 닫은 뒤 같은 item row로 복귀한다.
- S08은 문서 흐름 마지막에 있으며 작은 viewport에서 내용 위를 덮는 fixed CTA가 아니다.

## 수용 기준

- 사용자는 준비 상태의 이유와 해결할 항목을 한 번의 행동으로 연결한다.
- section 10개가 있어도 Card 중첩과 badge 과밀이 발생하지 않는다.
- 설계 항목과 관련 요구사항/근거/수용 기준을 Inspector에서 왕복한다.
- workable과 ready의 차이를 색상이나 숫자 없이 설명한다.
- S08 실행 후 사용한 design revision이 문서 생성 상태에 표시된다.
