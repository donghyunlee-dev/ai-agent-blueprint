# 설계 보드와 준비 상태

## F-DESIGN-WORKABLE

주 시안은 [설계 준비 화면](../../blueprint-design/README.md)이다. 공통 프레임에서 `설계`를 현재 단계로 표시하고, 실제 readiness 상태·이유, 5개 표현 카드, 기존 10개 세부 영역, 요구사항 명세 생성 gate를 순서대로 읽는다. 대화 단계의 우측 요약은 같은 확정 aggregate에서 출발하며 선택된 결정에서 해당 영역과 대화 근거로 연결한다.

```text
프로젝트 제목 · 설계 단계 · 저장 상태
[S01] 설계 준비 상태   [S02] 부족/작업 가능/준비 완료와 원인
[S03] 해결할 blocker 보기
┌─ 5개 표현 카드 ───────────────────────────────────────────┐
│ [S04] 제품과 문제  [S05] 사용자  [S06] 기능과 범위        │
│ 데이터와 연동       보안과 운영                            │
└───────────────────────────────────────────────────────────┘
카드 선택 → 원본 영역·항목·blocker 상세 [S09]~[S13]
[S07] 요구사항 명세 생성 gate 이유   [S08] 요구사항 명세 생성
```

## 상태 위계와 원본 영역

- S02는 `computeDesignReadiness()`의 `insufficient/workable/ready`와 원인을 사용한다. 시안의 `4/5`는 새 점수, 완료율 또는 생성 gate가 아니다.
- S04~S06을 포함한 5개 카드는 기존 10개 `DESIGN_SECTIONS`를 묶는 표현이다. 그룹은 `product/problem/outcomes`, `users/scenarios`, `features/scope`, `data`, `identity/operations` 순서다. 각 원본 영역은 정확히 한 그룹에 포함한다.
- 원본 10개 영역은 제품 정의, 문제와 목표, 사용자와 역할, 시나리오, 핵심 기능과 수용 기준, 범위와 제외 범위, 데이터와 외부 연동, 인증과 권한, 운영·배포·보안 제약, 성공 기준과 위험이다.
- 각 카드에는 child 영역의 상태, 항목, blocker, conflict, deferred와 review_required를 잃지 않고 표시한다. 카드 선택 후 원본 영역과 원인까지 한 번의 행동으로 이동한다.
- 확정 항목이 없는 원본 영역도 삭제하지 않는다. 빈 이유와 실제 가능한 대화·제안 검토 행동을 보여준다.

## 요구사항 명세 생성 gate

| 준비 상태 | S07 설명 | S08 |
| --- | --- | --- |
| insufficient | 필수 항목 또는 제안·충돌 처리 이유 | 비활성 이유와 해당 해결 행동 |
| workable | 명시적 보류를 오픈 이슈로 포함 | 생성 가능 |
| ready | 핵심 설계와 수용 기준이 준비됨 | 생성 가능 |

`canGenerateRequirements`는 기존 readiness 계산 결과를 따른다. 그룹 카드 상태를 합산하거나 새 수치를 만들어 판정하지 않는다.

## 결과 도식 보기

선택한 그룹 또는 관련된 확정 항목 사이의 관계가 데이터로 뒷받침되면 읽기 전용 도식 보기를 제공할 수 있다. 노드와 연결은 `confirmed` item/관계만 나타내며 source와 상세 화면으로 이동한다. proposal, deferred, conflict는 별도 상태로 남긴다. 도식 구조가 없거나 생성할 수 없으면 동일한 확정 항목을 텍스트 목록으로 보여준다. 시안의 다섯 그룹은 도식의 카테고리 표현으로 재사용할 수 있으나 readiness 계산과 원본 열 개 영역의 관계를 변경하지 않는다.

## 항목 상세

S09~S13은 선택한 원본 항목의 상태, 현재 값, 대화/파일 근거, 관계와 수용 기준을 보여준다. 기존 proposal 규칙을 거치지 않고 확정값을 덮어쓰지 않는다. 문서 직접 편집의 영향 미리보기·원자 적용은 별도 계약을 따른다.

## Mobile

5개 카드를 한 열로 읽고 선택하면 원본 영역과 항목을 연다. 항목 상세는 본문 뒤 또는 Drawer에 두며 닫은 뒤 원래 카드/행으로 포커스를 돌린다. S08은 내용과 OS safe area를 덮는 fixed CTA가 아니다.

## 수용 기준

- 준비 이유와 해결할 항목을 한 번의 행동으로 연결한다.
- 원본 영역 10개가 중복·누락 없이 남고 5개 카드의 표현이 기존 blocker와 gate를 바꾸지 않는다.
- 항목·근거·수용 기준을 왕복하며 색상이나 숫자만으로 상태를 설명하지 않는다.
- S08 실행 후 사용한 design revision이 문서 생성 상태에 표시된다.
