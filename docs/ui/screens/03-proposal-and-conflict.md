## Annotation 계약

| ID | 구현 | 성공 판정 |
| --- | --- | --- |
| P01 | 원래 답변 요약 | 원문 보기 가능, 수정 시 새 proposal 규칙 적용 |
| P02 | 발견 유형별 count | 숫자는 작업량이며 준비도 점수가 아님 |
| P03 | 처리 위치 | 현재/전체, 다음 미처리 이동 |
| P04 | composer | 검토 중에도 활성 |
| P05 | 중앙 header | pending count와 탭 제목 |
| P06 | 구분선 List | selected/hover/focus/상태 텍스트 |
| P07 | bulk summary | 충돌/오류 제외 수 명시 |
| P08 | 유형 Badge + 항목명 | 추가/수정/삭제와 대상 분리 |
| P09 | 제안값 | 확정값처럼 표시하지 않음 |
| P10 | EvidenceRef | 대화 turn 또는 파일 발췌로 이동 |
| P11 | 영향 | 항목/Requirements/PRD 섹션 이름 |

Inspector footer의 `승인`만 primary다. `거절`은 복구 가능한 제안 처리이므로 danger가 아니라 ghost다. `수정 후 승인`은 secondary다.

## 수정 후 승인

- P09가 `QuestionField` 편집 상태로 바뀐다.
- 원래 제안값을 초기값으로 사용하고 `수정 취소`, `수정값 승인`을 제공한다.
- 유효성 오류는 Inspector 안 field에 표시한다.
- 승인 성공 전까지 중앙 목록 상태는 `제안`이다.

## 일괄 승인 Modal

- 제목: `충돌 없는 제안 3개를 승인할까요?`
- 본문: 적용 3, 제외 1과 제외 사유
- 경고: 승인 후 설계 revision과 관련 문서 상태가 갱신됨
- 행동: `취소`, `3개 승인`
- 저장 transaction이 실패하면 Modal 안에 오류를 표시하고 모든 proposal을 원래 상태로 유지한다.

## Mobile

- `검토 3` 모드에서 P06 목록을 먼저 표시한다.
- 항목 선택 시 `WorkspaceDrawer`가 전체 폭에 가깝게 열리고 P08~P11을 표시한다.
- 승인 후 Drawer는 다음 항목으로 내용을 교체한다. 마지막 항목 처리 후 닫고 `검토할 제안이 없습니다` EmptyState로 이동한다.

## 수용 기준

- 일부 승인 후 나머지 proposal과 count가 정확히 유지된다.
- 제안·확정·충돌이 문구 없이 색상만으로 구분되지 않는다.
- 근거와 영향이 action보다 먼저 읽힌다.
- 충돌 해결 취소 시 확정 설계와 revision이 바뀌지 않는다.
- 모바일에서 승인 footer가 내용을 덮지 않고 마지막 영향 항목까지 스크롤된다.
