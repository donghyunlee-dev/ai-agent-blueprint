# 제안 검토와 충돌 해결

## F-PROPOSAL — Desktop

주 시안은 [제안 검토 화면](../../blueprint-design/README.md)이다. 공통 프레임에서 `제안 검토`를 현재 단계로 표시하고, 주 영역에 실제 미처리 제안의 내용·이유·근거·영향·행동을 둔다. 보조 영역에는 현재 aggregate의 확정 내용과 남은 검토 수를 표시한다. 답변을 다시 보거나 자유 입력을 계속하려면 대화 단계로 이동한다. 대화 단계 우측 요약은 [대화·결정 계약](../../product/04-conversation-process.md)에 따라 승인 transaction 성공 후 같은 aggregate revision으로 갱신한다.

```text
공통 프레임: 프로젝트 제목 · 제안 검토 단계 · 저장 상태
┌─ 제안 검토 주 영역 ──────────────────────────┬─ 보조 상태 ─────────┐
│ [P05] 검토할 제안 N개                       │ [P01] 답변 맥락      │
│ [P06] 제안 항목 목록                         │ [P02] 발견 결과      │
│ [P08] 현재 항목 유형·제목                    │ [P03] 처리 위치      │
│ [P09] 제안 내용 · [P10] 이유/근거             │ 확정 내용·남은 수    │
│ [P11] 영향 · 거절 · 수정 후 승인 · 승인       │                      │
│ [P07] 일괄 처리 가능 수                      │                      │
└─────────────────────────────────────────────┴──────────────────────┘
```

| ID | 판정 |
| --- | --- |
| P01–P03 | 원래 사용자 turn과 발견 내용을 source link로 보여준다. 수는 readiness 점수가 아니다. |
| P04 | 자유 composer는 대화 단계에서 계속 접근 가능하다. |
| P05–P07 | 대기·충돌·일괄 가능 수를 실제 proposal 상태에서 계산한다. |
| P08–P09 | 추가/수정/삭제 유형과 제안값을 확정값과 구분한다. |
| P10–P11 | 대화 turn 또는 파일 근거와 영향받는 항목·문서로 이동할 수 있다. |

제안별 `승인`이 primary, `수정 후 승인`은 secondary, `거절`은 복구 가능한 보조 행동이다. 시안의 `검토 완료`는 미처리 제안과 충돌이 실제로 0개일 때만 다음 행동으로 해석한다. 예시 프로젝트와 제안을 화면에 넣지 않는다. 대화 단계에서 넘어온 제안은 원본 turn, 첨부 발췌 또는 11개 추천 중 선택된 후보를 추적할 수 있어야 한다. 후보 목록 자체는 승인 전까지 확정 설계에 영향을 주지 않는다.

## 수정 후 승인

- 현재 제안값을 편집 필드의 초기값으로 보여주고 취소·검증 오류를 같은 위치에서 처리한다.
- 승인 성공 전에는 항목이 제안 상태로 남는다.
- 성공 시 다음 미처리 제안 또는 다음 대화 행동으로 포커스를 이동한다. 저장 실패 시 입력과 기존 상태를 유지한다.

## F-CONFLICT

현재 확정값, 새 제안값, 각각의 근거와 영향받는 항목을 비교한다. `기존 값 유지`, `새 제안 사용`, `직접 수정` 중 명시적으로 선택한 뒤 적용한다. 모바일에서는 현재값 다음에 제안값을 세로로 읽는다. 취소·저장 실패 시 확정 설계와 revision을 바꾸지 않는다.

## 일괄 처리

- 충돌 또는 재검토가 필요한 항목을 제외하고 적용·제외 수와 이유를 실행 전에 보여준다.
- 승인·거절은 기존 원자적 transaction으로 처리한다. 실패 후 일부만 성공한 것처럼 보이지 않는다.
- 확인 Modal의 포커스 진입·복귀, Escape, 오류와 긴 목록 스크롤을 검증한다.

## Mobile

제안 목록과 실제 대기 수를 먼저 읽는다. 선택 항목의 근거·영향·행동은 목록 뒤에 배치하거나 접근 가능한 Drawer로 연다. 마지막 영향 항목과 footer가 겹치지 않고, 닫은 뒤 원래 항목으로 포커스가 돌아간다.

## 수용 기준

- 단건·수정·거절·일괄·충돌 처리 후 남은 제안 수와 확정 설계가 정확하다.
- 제안·확정·충돌을 텍스트와 아이콘으로 구분한다.
- 근거와 영향이 승인 행동보다 먼저 읽힌다.
- 모바일과 키보드에서 저장 실패·취소·다음 항목 포커스가 기존 transaction 계약을 보존한다.
