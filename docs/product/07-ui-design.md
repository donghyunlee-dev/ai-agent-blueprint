# UI 디자인 명세

이 문서는 제품 전체의 시각 방향, 정보 구조와 공통 상호작용 원칙을 정의한다. 실제 구현에 필요한 화면별 위치, 구조 치수, 여백, 컴포넌트, 토큰, 스크롤, 반응형 상태와 완료 검수 기준은 [상세 화면 설계](../ui/README.md)를 따른다.

## 화면 논지

Blueprint는 대화, 제안 검토, 설계와 문서를 단계별로 이어서 다루는 제품 설계 작업 공간이다. 사용자는 현재 단계와 다음 가능한 행동을 알 수 있고, 이전 결정은 해당 단계의 요약·상세에서 확인할 수 있어야 한다.

## 시각 방향

- 문서와 대화를 가장 먼저 읽을 수 있는 절제된 작업 도구
- 넓은 중립 배경과 명확한 텍스트 위계
- 하나의 강조색으로 선택, 진행과 주요 행동 표현
- 장식용 카드보다 정보 관계와 작업 상태를 우선
- 문서 편집과 검토가 긴 시간에도 피로하지 않은 밀도

## 시각 참고 원칙

- [Blueprint 개편 시안](../blueprint-design/README.md)에서 현재 화면의 주 이미지를 확인한다. 시안에 없는 상태는 [기존 template 이미지 목록](../template/README.md)을 참고한다.
- 캡처는 정보 위계, 작업 영역, 문서 밀도와 상호작용 패턴의 참고 자료다. 화면 이미지를 그대로 제품 자산으로 사용하지 않는다.
- 기능, 상태 전이와 데이터 규칙은 제품 명세가 정의하고, 키보드·포커스·대비·반응형 기준은 화면 명세가 추가로 정의한다.
- 제품 화면은 기존 React 구조와 semantic HTML/CSS를 사용한다. 외부 UI package나 디자인 시스템을 새로 추가하지 않는다. 반복되는 값만 앱 범위 CSS custom properties로 묶는다.
- 재사용 컴포넌트는 Blueprint 코드에서 두 곳 이상이 같은 동작을 공유할 때만 추출한다.

구현 계약과 캡처 확인 절차는 [UI 참고 이미지 통합 명세](09-ui-reference-integration.md)를 따른다.

## 정보 구조

### 로그인

1. 제품명과 한 문장 가치
2. Google 로그인 안내
3. `Google로 계속` 단일 주요 행동
4. 인증 오류·세션 만료와 재시도
5. 브라우저 로컬 저장 안내

로그인 화면에는 이메일·비밀번호 필드를 만들지 않는다. 인증 확인 중에는 제품 홈을 노출하지 않고 짧은 로딩 상태만 표시한다. 세부 조립과 치수는 [로그인·세션 화면 청사진](../ui/screens/00-login-and-session.md)을 따른다.

### 로그인 후 홈

1. 제품 정체성과 한 문장 가치
2. 새 Blueprint 입력
3. 파일 첨부와 예시 시작점
4. 최근 프로젝트
5. 산출물과 진행 방식 설명

로그인 후 홈의 첫 화면에서 사용자가 바로 아이디어를 입력할 수 있어야 한다. 긴 마케팅 설명을 읽은 뒤 시작하도록 만들지 않는다.

### 작업 공간

```text
프로젝트 제목 · 저장 상태 · 사용자 행동
대화 → 제안 검토 → 설계 → Requirements → PRD
────────────────────────────────────────────
현재 단계의 주 작업 영역  │ 해당 단계의 보조 요약·목차·상세
필요한 때만 열리는 제안·충돌·영향 검토 오버레이
```

### 영역별 책임

| 영역 | 역할 |
| --- | --- |
| 공통 프레임 | 지원되는 탐색, 프로젝트 식별, 저장 상태, 사용자 행동 |
| 단계 탐색 | 대화·제안 검토·설계·Requirements·PRD의 실제 현재 위치와 gate |
| 주 작업 영역 | 선택 단계의 대화, 제안, 설계 또는 문서 |
| 보조 영역 | 해당 단계의 요약, 근거, 목차 또는 선택 항목 상세 |

인증된 화면의 상단바에는 현재 사용자 이메일과 로그아웃 메뉴를 포함한다. 모바일에서는 별도 사용자 메뉴로 접되 같은 의미와 키보드 접근을 유지한다.

## 로그인 후 홈 화면

### 첫 화면 구성

- 브랜드 텍스트와 실제 목적지만 있는 간결한 탐색
- 제목: 아이디어를 검토 가능한 제품 설계로 만든다는 결과 표현
- 한 문장의 설명
- 3~5줄 입력 가능한 시작 입력창
- `Blueprint 시작` 주요 행동
- 파일 첨부 행동
- 실제 구현된 예시가 있을 때만 사용자가 눌러 입력창에 적용할 수 있는 시작점

실제 데이터와 기능 없이 제품 미리보기, 샘플 프로젝트, 시작 카드를 채우지 않는다.

### 최근 프로젝트

- 프로젝트명
- 마지막 수정 시간
- 준비도 상태
- 현재 작업 문서
- 이어서 작업 행동

최근 프로젝트가 없으면 사용 예시와 첫 시작 방법을 보여준다.

최근 사용 순으로 최대 20개를 표시한다. 21번째 프로젝트를 만들면 가장 오래된 프로젝트의 제목과 포함 데이터를 확인 화면에 보여주고, 사용자가 삭제를 확인해야 계속한다.

## 작업 공간 레이아웃

### 데스크톱

- 선택한 단계가 넓은 주 작업 영역을 차지한다.
- 대화에서는 질문과 composer가 중심이고 확정·미결정 요약을 보조 영역에 둔다.
- 제안에서는 항목별 승인·수정·거절과 근거를 함께 읽는다. 설계에서는 준비도 개요와 10개 세부 영역을 연결한다.
- Requirements/PRD에서는 문서 목차, 섹션 목록·상세, 편집·검토 행동을 단계 안에 배치한다.
- 기존 대화 너비 조절 값은 대화 레이아웃에 적용되는 동안 보존한다. 모든 단계에 동일한 3패널 폭을 강제하지 않는다.

### 태블릿

- 주 작업 영역을 먼저 읽고 보조 요약·상세는 콘텐츠 폭에 따라 아래로 이동하거나 명시적 제어로 연다.
- 현재 단계, 입력, 선택 항목과 스크롤 기준을 뷰포트 전환 시 유지한다.

### 모바일

- 현재 단계의 콘텐츠와 행동을 한 열로 읽는다. 단계 전환과 해당 단계의 보조 영역 진입은 별도 제어로 제공한다.
- 입력 중에는 대화 composer를 접근 가능하게 유지하고 콘텐츠와 OS safe area를 가리지 않는다.
- 제안 대기 수와 오류는 필요한 위치에 텍스트로 표시한다. 선택 폼은 한 열로 배치한다.
- 상세를 Drawer로 구현할 때 닫힌 DOM이 Tab 순서에 남지 않도록 `inert` 또는 동등한 포커스 차단을 적용한다.

## 대화 단계

### 메시지 표현

- 사용자 메시지, Agent 설명, 시스템 상태와 오류를 서로 다른 의미로 구분한다.
- Agent 이름이나 모델 정보보다 현재 작업과 결과를 우선 표시한다.
- 긴 분석은 접을 수 있는 작업 상세로 제공한다.
- 완료된 질문의 답은 요약 형태로 유지하며 편집 진입점을 제공한다.

### 질문 카드

- 질문 제목
- 질문 이유 또는 쉬운 설명
- 진행에 필요한 경우 필수 표시
- 선택 폼
- 직접 입력 또는 불확실성 행동
- 제출 버튼

질문 카드는 현재 대화의 주요 행동이므로 주변 메시지보다 명확한 위계를 가진다.

### 작업 상태

```text
답변 분석 중
✓ 관련 사용자 2개 발견
• 기능 후보 정리 중
• 다음 질문 준비 중
```

진행률을 알 수 없는 작업에 임의의 백분율을 표시하지 않는다. 단계와 완료 여부를 보여준다.

## 선택 폼

### 단일 선택

- 옵션이 5개 이하이면 라디오 카드 또는 버튼 목록을 사용한다.
- 선택 즉시 제출하지 않고 사용자가 내용을 확인할 수 있게 한다.
- 설명이 필요 없는 이진 선택은 간결한 버튼으로 표시한다.

### 복수 선택

- 체크 상태, 선택 수와 최대 선택 수를 표시한다.
- 복수 선택과 우선순위 지정은 별도 화면으로 구분한다.
- 직접 입력 항목은 선택 목록 안에서 동일한 지위로 표시한다.

### 추천

- 추천 배지와 한 줄 이유를 표시한다.
- 추천값을 자동 선택하지 않는다.
- 추천 근거를 열어 현재 어떤 결정이 사용되었는지 확인할 수 있게 한다.

### 미정 처리

`잘 모르겠어요`, `추천해 주세요`, `나중에 결정`은 보조 행동으로 제공한다. 미정으로 진행한 항목은 준비도와 최종 문서에서 다시 찾을 수 있어야 한다.

### 제안 처리와 다음 질문

현재 질문에서 만들어진 제안이 남아 있으면 다음 질문 CTA를 비활성화하고 남은 처리 수를 표시한다. 사용자는 제안 처리 전에도 자유 대화를 입력할 수 있다.

## 설계 단계

### 설계 개요

상단 5개 요약 카드는 기존 10개 설계 영역을 그룹으로 보여준다. 각 항목은 원래 상태와 관련 요구사항 수를 유지하며 선택하면 10개 원본 영역과 상세로 이동한다. 5개 카드는 새 점수나 생성 gate가 아니다.

### 상태 표현

| 상태 | 표현 원칙 |
| --- | --- |
| 확정 | 체크 아이콘과 중립적인 확정 라벨 |
| 제안 | 강조색 테두리와 검토 필요 라벨 |
| 미정 | 빈 원형 아이콘과 미정 라벨 |
| 재검토 | 경고 아이콘과 영향 설명 |
| 충돌 | 비교 화면으로 이동하는 오류 라벨 |

색상과 함께 아이콘, 텍스트를 사용한다.

## 변경안 검토

- 변경 유형과 대상 이름을 카드 상단에 표시한다.
- 수정 제안은 기존 값과 새 값을 읽기 쉬운 전후 비교로 표현한다.
- 이유와 근거는 기본적으로 짧게 표시하고 상세를 펼칠 수 있게 한다.
- `거절`, `수정 후 승인`, `승인`의 행동 우선순위를 명확히 한다.
- 여러 제안이 있으면 현재 위치와 남은 수를 표시한다.
- 일괄 처리는 충돌 없는 항목에만 제공한다.

## 문서 화면

### 공통

- Requirements와 PRD는 공통 단계 탐색에서 전환한다.
- Requirements가 준비 완료되기 전에는 PRD 단계에 잠금 이유와 필요한 검토 항목으로 이동하는 행동을 제공한다.
- 문서 목차를 제공하고 현재 섹션을 표시한다.
- 본문은 읽기 적합한 최대 폭을 유지한다.
- 섹션 단위 편집과 Agent 보완 행동을 제공한다.
- 생성 기준 revision, 마지막 저장 시간과 동기화 상태를 표시한다.
- 직접 편집 저장 전에 변경될 공통 설계 항목과 최신 상태가 바뀔 다른 문서를 영향 미리보기로 보여준다.
- 사용자가 영향 내용을 확인한 뒤 저장하면 공통 설계에 즉시 반영한다.
- 저장 후 영향받은 다른 문서의 최신 상태를 표시한다.

## 준비도 표현

- 숫자 점수와 원형 퍼센트 차트를 사용하지 않는다.
- `부족`, `작업 가능`, `준비 완료` 상태와 영역별 누락·미정·확정을 표시한다.
- 명시적 미정은 문서 생성을 막지 않으며 생성 결과의 오픈 이슈로 이어진다는 점을 설명한다.

## 파일과 개인정보 안내

- 업로드 영역에 TXT, Markdown, 텍스트 PDF, 파일당 10MB와 최대 5개 제한을 표시한다.
- 프로젝트별 첫 AI 전송 전에 외부 AI 처리와 필요한 발췌 전송을 한 번 안내한다.
- 각 파일 행에 민감정보 제거 안내와 추출 성공·실패 상태를 표시한다.

## 언어

MVP의 UI, Agent 메시지와 생성 문서는 한국어로 제공한다. 언어 선택 제어는 표시하지 않는다.

## 설정 가이드

- Agent가 확정 설계에 맞춰 전체 가이드를 생성한다.
- 생성 중 작업 단계와 사용한 설계 revision을 표시한다.
- 사용자 승인 전에는 초안 라벨을 표시한다.
- 설치 명령, 환경 변수와 외부 링크를 빠르게 검토할 수 있게 구분한다.

## 404 화면

이전 `/survey`, `/prd`와 존재하지 않는 경로에는 새 프로젝트 시작과 홈 이동만 제공하는 공통 404 화면을 표시한다. 이전 화면이나 자동 리다이렉트는 제공하지 않는다.

### 요구사항명세서

- 요구사항 ID, 우선순위, 상태와 수용 기준을 빠르게 스캔할 수 있어야 한다.
- 실제 문서 section과 연결된 목차로 내용을 찾는다. 별도 검색·필터 기능은 추가하지 않는다.
- 수용 기준이 없거나 재검토가 필요한 요구사항을 찾을 수 있게 한다.

### PRD

- 제품 개요와 문제, 목표, 사용자, 범위, 성공 기준과 위험을 문서 흐름으로 읽게 한다.
- 기술 구현 속성은 필요한 경우 연결된 요구사항 상세로 이동시킨다.
- 미정 사항과 가정은 문서 말미의 별도 섹션에 모은다.

## 빈 상태

빈 상태는 다음 세 가지를 설명한다.

1. 이 영역에 무엇이 표시되는가
2. 결과를 만들려면 무엇이 필요한가

문서 준비 전에는 부족한 설계 영역으로 이동하는 행동을 제공한다. 오류 상태와 빈 상태를 같은 화면으로 표현하지 않는다.

## 타이포그래피와 밀도

- 화면 제목, 섹션 제목, 본문, 메타데이터의 네 단계 위계를 사용한다.
- 문서 본문은 대화와 메타데이터보다 여유 있는 줄 높이를 사용한다.
- 전체 대문자 라벨과 작은 회색 글자는 짧은 메타데이터에만 사용한다.
- 얇은 회색 텍스트로 핵심 안내를 표현하지 않는다.
- 카드 중첩보다 여백, 구분선과 제목 위계로 영역을 나눈다.

## 접근성

- 패널, 문서 탭, 질문과 변경안 영역에 의미 있는 landmark와 이름을 제공한다.
- 라디오와 체크박스는 실제 입력 의미를 유지한다.
- 오류는 해당 입력과 프로그램적으로 연결한다.
- 비동기 작업과 제안 추가는 적절한 live region으로 알린다.
- 포커스가 모달과 드로어 밖으로 빠지지 않게 한다.
- 제안 승인 후 다음 검토 항목 또는 다음 질문으로 예측 가능한 포커스를 이동한다.
- 모션 감소 설정을 존중한다.

## 검증 기준

- 로그인 화면에서는 인증 행동이, 로그인 후 홈에서는 제품 가치와 시작 행동이 하나의 구성으로 읽힌다.
- 사용자는 현재 질문과 그 이유를 찾을 수 있다.
- 확정 내용과 AI 제안을 혼동하지 않는다.
- 대화하면서 문서가 어디에 반영되는지 확인할 수 있다.
- 문서 탭을 바꿔도 대화와 프로젝트 맥락이 유지된다.
- 데스크톱과 모바일에서 검토 대기 항목을 놓치지 않는다.
- 키보드만으로 질문 답변, 제안 승인과 문서 이동이 가능하다.
