# 제품 정의

## 제품 한 줄 정의

SFOOD Agent Blueprint는 사용자가 AI와 연속적으로 대화하고 선택지를 검토하면서 제품 설계를 축적하고, 같은 설계 데이터에서 요구사항명세서·PRD·실행 가이드를 완성하는 작업 공간이다.

서비스는 AX Login의 사내 Microsoft 인증을 완료한 직원에게만 제공한다.

## 해결할 문제

초기 아이디어는 대화, 메모, 회의 자료와 선택되지 않은 기술 후보로 흩어져 있다. 비개발자는 어떤 정보를 먼저 정해야 하는지 알기 어렵고, 개발자는 생성된 문서의 근거와 확정 여부를 판단하기 어렵다. 문서를 각각 생성하면 목표, 기능, 기술 결정이 서로 어긋나기도 한다.

Blueprint는 다음 문제를 해결한다.

- 사용자가 모든 기획 항목을 미리 알지 못해도 설계를 시작할 수 있어야 한다.
- 이미 답한 내용을 반복해서 묻지 않아야 한다.
- 자유로운 설명을 검토 가능한 결정 단위로 구조화해야 한다.
- AI가 만든 내용과 사용자가 확정한 내용을 구분해야 한다.
- 요구사항명세서와 PRD가 동일한 확정 설계를 사용해야 한다.
- 문서 생성 후에도 대화와 직접 편집으로 특정 항목을 보완할 수 있어야 한다.

## 주요 사용자

### 제품 아이디어를 가진 비개발자

- 만들고 싶은 서비스는 있지만 요구사항 작성 경험이 부족하다.
- 쉬운 질문과 예시를 통해 생각을 구체화하고 싶다.
- 기술 선택에는 추천과 이유가 필요하다.

### 제품 기획자 또는 프로젝트 리더

- 회의 자료와 기존 메모를 빠르게 제품 정의로 정리하고 싶다.
- 미정 사항과 충돌을 확인하고 팀이 검토할 문서를 만들고 싶다.
- 개발 전달 전에 범위와 수용 기준을 점검하고 싶다.

### 개발 담당자

- 결정의 근거, 기능 범위, 예외, 데이터와 운영 조건을 확인하고 싶다.
- 모호한 문장을 구현 가능한 요구사항으로 읽고 싶다.
- 확정되지 않은 가정이 구현 지시로 섞이지 않기를 원한다.

## 핵심 가치

### 대화로 시작

사용자는 아이디어를 설명하거나 자료를 첨부해 시작한다. Agent는 답변을 이해하고 현재 설계에서 가장 중요한 공백을 다음 질문으로 제시한다.

### 선택하며 확정

AI는 구조화된 선택지와 변경 제안을 제공한다. 사용자는 개별 항목을 승인, 수정 또는 거절하며 확정된 내용만 Blueprint에 반영한다.

### 하나의 설계에서 여러 문서 생성

제품 정의, 요구사항, 기술 결정과 제약은 하나의 프로젝트 데이터로 관리한다. 요구사항명세서, PRD와 실행 가이드는 이 데이터를 서로 다른 목적에 맞게 표현한다.

### 계속 보완 가능한 문서

문서는 마지막에 한 번 생성되는 결과가 아니다. 사용자는 문서 항목을 선택해 직접 수정하거나 Agent에 보완을 요청할 수 있다.

## 제품 원칙

1. AI 제안은 사용자 승인 전까지 확정 데이터가 아니다.
2. 질문 수보다 결정의 품질과 근거를 우선한다.
3. 한 번의 답변에서 여러 사실을 추출할 수 있다.
4. 질문은 남은 공백과 앞선 답변에 따라 달라진다.
5. 기술 용어는 설명과 추천 이유를 함께 제공한다.
6. 미정, 가정, 확정, 기각 상태를 화면과 문서에서 명확히 구분한다.
7. 사용자의 입력과 확정 설계는 오류와 재시도 중에도 보존한다.
8. 문서 간 정합성은 공통 데이터와 추적 가능한 항목 ID로 유지한다.
9. 질문·설명·추천·문서 생성은 난도에 맞는 AI 모델과 token 예산을 사용한다.
10. AI는 표현과 분석을 담당하며 질문 순서, 확정, 준비도와 process state는 코드가 결정한다.
11. 최종 문서는 계획, 작성, 검토와 제한된 보완을 분리해 생성한다.

## 제품 경계

### 포함

- AX Login과 사내 Microsoft 계정 인증
- 인증 세션, 로그아웃과 보호된 제품/API 접근
- Blueprint 프로젝트 생성과 재개
- AI 대화와 구조화 질문
- 선택형·자유 입력형 답변
- 복수 설계 항목 추출
- 제안 승인·수정·거절
- 제품 정의와 요구사항 누적
- 참고 파일의 텍스트 추출과 근거 연결
- 요구사항명세서 생성·편집·검토
- PRD 생성·편집·검토
- 맞춤 실행 가이드 구성
- Markdown 복사와 다운로드

### 포함하지 않음

- 유저플로우 캔버스
- 와이어프레임 생성과 편집
- 실시간 공동 편집
- 코멘트와 조직 권한
- Jira, GitHub 등 외부 서비스 쓰기
- 결제와 크레딧 관리
- 운영 환경의 장기 서버 프로젝트 저장

## MVP 운영 기준

- 사용자 인터페이스와 생성 문서는 한국어만 지원한다.
- 비인증 사용자는 로그인 화면만 볼 수 있고 홈과 Blueprint API는 사용할 수 없다.
- 로컬 프로젝트는 인증 사용자별 저장 namespace로 분리한다.
- 브라우저에는 최근 사용 프로젝트를 최대 20개까지 보관하며 초과 시 정리 대상을 확인받는다.
- AI 요청 실패 시 임의의 대체 결과를 만들지 않고 입력을 보존해 재시도한다.
- 결과물은 문서별 Markdown 복사와 다운로드로 제공한다.
- 프로젝트에는 하나의 연속 대화만 제공한다.
- 요구사항명세서를 먼저 완성한 뒤 PRD를 생성한다.
- 설정 가이드는 확정 설계에 맞춰 Agent가 새로 작성한다.
- 리빌드 이전 로컬 데이터와 기존 화면 URL은 지원하지 않는다.

## 성공의 정의

사용자는 초기 아이디어만으로 설계를 시작하고, Agent의 상황별 질문·설명·추천에 답하면서 확정 설계를 축적할 수 있어야 한다. AI는 한 답변에서 여러 설계 사실을 근거와 함께 제안하고 사용자의 선택을 대신하지 않아야 한다. 최종 결과에는 개발자가 추가 해석 없이 검토할 수 있는 기능 요구사항과 수용 기준이 포함되어야 하며, PRD와 요구사항명세서 사이에 서로 다른 목표·사용자·범위가 존재해서는 안 된다. 이 품질은 모델·prompt별 평가와 프로젝트 호출·token 예산을 함께 통과해야 한다.
